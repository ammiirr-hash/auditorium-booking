# Заявка на тему проекта

## 1. Название проекта

**Информационная система бронирования аудиторий преподавателями университета**

## 2. Организация

**Казанский государственный энергетический университет (КГЭУ)**, учебно-методическое управление / подразделение, ответственное за расписание и распределение аудиторий.

## 3. Проблема

При бронировании аудиторий информация о занятых и свободных аудиториях может храниться в разных источниках. Из-за этого сложно быстро определить доступность конкретной аудитории, отследить ответственное лицо и текущее состояние заявки. Также существует риск пересечения бронирований одной аудитории на одно и то же время.

## 4. Цель проекта

Разработать информационную систему, которая позволит преподавателям создавать заявки на бронирование аудиторий, ответственным сотрудникам назначать исполнителей, а назначенным ответственным лицам обрабатывать заявки и изменять их состояние.

## 5. Основная сущность

**Бронь аудитории** — основная сущность системы.

Для брони используется машинный идентификатор `id` и человекочитаемый номер `number`.

## 6. Справочник

Система использует справочник **Аудитории**.

Связь брони с выбранной аудиторией осуществляется через числовой идентификатор `auditoriumId`.

## 7. Роли

### Преподаватель

* создаёт бронь аудитории;
* указывает аудиторию и данные бронирования;
* не назначает исполнителя;
* не изменяет статус заявки.

### Диспетчер расписания

* просматривает созданные брони;
* назначает ответственного исполнителя;
* не создаёт брони;
* не изменяет статус заявки.

### Ответственный за аудитории

* получает назначенную ему бронь;
* переводит свою назначенную бронь из `New` в `InProgress`;
* обрабатывает бронь;
* изменяет статус только назначенных ему записей.

## 8. Процесс

Основной процесс состоит из отдельных действий:

1. Преподаватель создаёт бронь.
2. Созданная бронь получает статус `New`.
3. Диспетчер расписания назначает ответственного исполнителя.
4. Ответственный за аудитории принимает назначенную ему бронь в работу.
5. Бронь переводится в `InProgress`.
6. После завершения обработки бронь может быть переведена в `Closed`.
7. При отмене бронь может быть переведена в `Cancelled`.

**Назначение исполнителя и изменение статуса являются отдельными действиями.**

## 9. Статусы

В системе используются четыре статусных кода:

* `New` — бронь только создана;
* `InProgress` — назначенный исполнитель взял бронь в работу;
* `Closed` — обработка брони завершена;
* `Cancelled` — бронь отменена.

## 10. Данные при создании

При создании брони указываются:

* `title` — название/назначение бронирования;
* `auditoriumId` — идентификатор аудитории из справочника;
* `description` — описание бронирования.

Дополнительно в рамках развития проекта предполагается хранение даты, времени начала и окончания бронирования, количества участников и назначения аудитории.

## 11. Основные экраны

В рамках учебного минимума предусматриваются:

1. **Список броней** — просмотр и фильтрация заявок.
2. **Создание брони** — создание новой заявки преподавателем.
3. **Авторизация** — вход пользователя в систему.

## 12. Технологический стек

* **Frontend:** Vue 3
* **Backend:** ASP.NET Core
* **Database:** PostgreSQL

## 13. Развитие проекта

В рамках дальнейшего развития проекта планируется:

1. **Данные и процесс:** хранение даты, времени начала и окончания бронирования, количества участников и назначения аудитории.
2. **Контроль процесса:** автоматическая проверка пересечения бронирований и отклонение заявки при занятости аудитории.
3. **Интеграция:** возможность интеграции с системой учебного расписания университета.
4. **Масштабирование:** поддержка нескольких учебных корпусов и большого количества аудиторий с поиском и фильтрацией.

Данные возможности рассматриваются как развитие проекта и не входят в обязательный минимум лабораторной работы №1.

## 14. Границы семестрового проекта

В рамках семестрового проекта реализуется минимально необходимый процесс создания, назначения и обработки брони аудитории.

Интеграция с внешними системами, расширенная проверка расписания, масштабирование на несколько корпусов и дополнительные функции рассматриваются как направления дальнейшего развития проекта.

## 15. Результат

Результатом проекта должна стать веб-информационная система, в которой можно создать бронь аудитории, назначить ответственного исполнителя и последовательно обработать заявку с использованием установленных статусов.
