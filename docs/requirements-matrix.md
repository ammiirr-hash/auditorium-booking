# ЛР2. Матрица требований — Бронь аудитории

## 1. Назначение

Матрица связывает критерии из ЛР1 с сущностями ER-модели, полями базы данных и API.

## 2. Матрица трассируемости

| Критерий ЛР1 | Сущность | Поля / данные | API |
|---|---|---|---|
| Создание брони аудитории | `Booking` | `id`, `number`, `title`, `auditoriumId`, `description`, `status` | `POST /api/bookings` |
| Назначение исполнителя | `Booking`, `User` | `assigneeUserId` | `PATCH /api/bookings/{id}/assignee` |
| Изменение статуса брони | `Booking` | `status` | `PATCH /api/bookings/{id}/status` |

## 3. Дополнительные связи

| Требование | Реализация |
|---|---|
| Получение списка броней | `GET /api/bookings` |
| Получение одной брони | `GET /api/bookings/{id}` |
| Выбор аудитории | `Booking.auditoriumId → Auditorium.id` |
| Выбор исполнителя | `Booking.assigneeUserId → User.id` |
| Отмена брони | Статус `Cancelled` |
| Пустой список | `200 OK` и `[]` |
| Создание объекта | `201 Created` |
| Удаление брони | Не предусмотрено API |

## 4. Проверка соответствия

Все основные операции процесса бронирования представлены в API:

- создание брони;
- просмотр списка броней;
- просмотр одной брони;
- назначение исполнителя;
- изменение статуса;
- отмена через статус `Cancelled`.

ER-модель и API-контракт согласованы между собой.
